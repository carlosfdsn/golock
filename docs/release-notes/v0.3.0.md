## GoLock v0.3.0

Security hardening, a responsive interface and a much larger test suite since v0.2.0.

### Security and reliability
- The vault key is wiped from memory when you lock the vault and when the app closes.
- The master password is no longer kept in memory. It is checked against the vault only when needed (export, recovery key).
- All vault state is now protected by a mutex, so a double click, auto-lock and an import can no longer race each other.
- Clipboard clearing only wipes the clipboard if it still holds the copied password, and a newer copy cancels the older timer.
- Import reads at most 20 MB even if the file grows while reading, ignores oversized entries and rolls back completely if saving to disk fails.
- Field limits: name and username up to 200 characters, password up to 1024.
- Deleting an entry now handles disk errors: the screen refreshes and shows the error instead of hiding a password that is still stored.
- Enter plus click (or a double click) on login no longer triggers two requests.

### Fixes
- Category detection: keywords of up to 3 letters (`xp`, `c6`, `max`, `pix`) now match whole words only. "Expedia" is no longer a bank and "Maxi Atacado" is no longer streaming.
- The mascot image is bundled into the build instead of being loaded by path.
- Removed three duplicated dialogs (recovery key, forgot password, generate key) from `index.html`.

### Interface
- Responsive layout for phone, tablet and desktop: entries use 1 to 3 columns, dialogs open as bottom sheets on small screens, touch targets are larger and safe areas are respected.
- The window is resizable. The initial size is fitted to the active display and the minimum size adapts to small screens.

### Quality
- New tests for the vault lifecycle, recovery key, legacy migration and import/export.
- CI now runs `gofmt`, `govulncheck`, `go vet` and `go test -race`.
- Requires Go 1.27.2 (patched toolchain).
- READMEs updated (English and Portuguese).
